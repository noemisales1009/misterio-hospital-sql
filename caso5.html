Caso 5: a conta que não fecha

AUDITORIA

Faturamento · agosto de 2026

A auditoria de contas viu que o total cobrado dos convênios em agosto está acima do esperado. Cada cobrança entra em um lote, assinado por um faturista. Existem três tipos de erro: valor acima da tabela, linha cobrada duas vezes e procedimento que não foi realizado.

Um pouco de erro em cada lote é normal, é gente trabalhando. Um lote, porém, concentra muito mais. Você vai medir cada tipo de erro, juntar os três e achar o lote que foge do padrão. A resposta é o código do lote.

A novidade deste caso é juntar resultados com WITH e UNION ALL, além de comparar valores com numeric. Faça uma etapa por vez. Travou? Abra a dica, depois a solução.

Atenção: nas datas deste caso

Aqui a data do atendimento é uma data de verdade (tipo date). Escreva entre aspas simples, no formato ano-mês-dia.

Neste casoEscreva assim
✅ CertoWHERE data = '2026-08-31'
✅ CertoWHERE data BETWEEN '2026-08-01' AND '2026-08-31'
❌ ErradoWHERE data = 20260831, porque número não é data aqui

Nos Casos 1 a 3 a data era um número, como 20260310. Para saber qual é o caso de cada coluna, olhe o tipo no mapa das tabelas: integer é número, e date ou timestamp é data de verdade.

1

Acima da tabela

JOIN · numeric · ROUND · SUM
Situação

Primeiro erro: a linha foi cobrada por um valor maior que o da tabela. Para cada linha, o esperado é o preço de uma unidade vezes a quantidade. Compare com o que foi cobrado.

ComandoO que fazNo dia a dia
JOIN procedimentotraz o preço de tabela para cada linha cobrada“quanto custa de verdade”
valor_tabela * quantidadeconta entre colunas: o valor esperado da linha“3 diárias de R$ 420”
valor_cobrado > valor esperadocompara duas colunas“cobrou acima da tabela”
SUM(a - b)soma a diferença de todas as linhas“excesso total”
ROUND(x, 2)arredonda em reais e centavos“R$ 9.897,86”
Sua missão
  • Liste as linhas de cobranca em que valor_cobrado é maior que valor_tabela * quantidade, com o lote, o procedimento e os dois valores.
  • Quantas são, e qual o excesso total em reais, com 2 casas decimais?
Dica

JOIN procedimento p ON p.id = c.procedimento_id e WHERE c.valor_cobrado > p.valor_tabela * c.quantidade. O excesso de cada linha é a diferença entre os dois. Some com SUM(...) e arredonde com ROUND(..., 2).

Ver solução
SELECT c.id, c.lote, p.descricao, c.quantidade,
       c.valor_cobrado,
       p.valor_tabela * c.quantidade AS esperado
FROM cobranca c
JOIN procedimento p ON p.id = c.procedimento_id
WHERE c.valor_cobrado > p.valor_tabela * c.quantidade
ORDER BY c.id;
SELECT COUNT(*) AS linhas,
       ROUND(SUM(c.valor_cobrado - p.valor_tabela * c.quantidade), 2) AS excesso
FROM cobranca c
JOIN procedimento p ON p.id = c.procedimento_id
WHERE c.valor_cobrado > p.valor_tabela * c.quantidade;

Para conferir: 27 linhas e excesso de R$ 9.897,86.

2

Cobradas duas vezes

GROUP BY · HAVING · NOT IN (SELECT MIN)
Situação

Segundo erro: o mesmo procedimento, no mesmo atendimento, cobrado mais de uma vez. Primeiro você enxerga os pares. Depois isola só as linhas repetidas, sem contar a original, para o lote ficar com a culpa certa.

ComandoO que fazNo dia a dia
GROUP BY a, bagrupa pelo par de colunas“mesmo atendimento e mesmo procedimento”
HAVING COUNT(*) > 1só grupos com mais de uma linha“cobrado mais de uma vez”
MIN(id)o menor id do grupo: a linha original“a primeira cobrança”
NOT IN (SELECT MIN(id) …)fica com tudo, menos a original“só as cópias”
Cuidado

Se você apontar as duas linhas do par como erro, vai contar o dobro. A original é legítima. Erro é só a cópia: a linha cujo id não é o menor do grupo.

Sua missão
  • Ache os pares (atendimento e procedimento) que aparecem mais de uma vez em cobranca.
  • Liste só as linhas repetidas (as cópias), com o lote. Quantas são?
Dica

Pares: GROUP BY atendimento_id, procedimento_id HAVING COUNT(*) > 1. Cópias: WHERE id NOT IN (SELECT MIN(id) FROM cobranca GROUP BY atendimento_id, procedimento_id). A subconsulta devolve o id da primeira linha de cada grupo.

Ver solução
SELECT atendimento_id, procedimento_id, COUNT(*) AS vezes
FROM cobranca
GROUP BY atendimento_id, procedimento_id
HAVING COUNT(*) > 1
ORDER BY atendimento_id;
SELECT id, lote, atendimento_id, procedimento_id, valor_cobrado
FROM cobranca
WHERE id NOT IN (
  SELECT MIN(id)
  FROM cobranca
  GROUP BY atendimento_id, procedimento_id
)
ORDER BY id;

Para conferir: 31 pares, e portanto 31 linhas repetidas.

3

Cobradas e não realizadas

LEFT JOIN · IS NULL com 2 colunas
Situação

Terceiro erro, o mais grave: o procedimento foi cobrado, mas não consta como realizado. A chave da execução tem duas colunas, atendimento e procedimento, então o JOIN também usa as duas.

ComandoO que fazNo dia a dia
LEFT JOIN … ON a AND ba chave tem duas colunas, então o ON também tem“atendimento e procedimento”
e.atendimento_id IS NULLsem par em execucao: não foi realizado“cobrado, mas não consta como feito”
COUNT(*) e SUM(valor)quantas linhas e quanto dinheiro“30 linhas, R$ 25.462,00”
Sua missão
  • Liste as linhas de cobranca que não têm correspondente em execucao (mesmo atendimento e mesmo procedimento).
  • Quantas são, e qual o valor total cobrado nelas?
Dica

LEFT JOIN execucao e ON e.atendimento_id = c.atendimento_id AND e.procedimento_id = c.procedimento_id e depois WHERE e.atendimento_id IS NULL.

Ver solução
SELECT c.id, c.lote, c.atendimento_id, c.procedimento_id, c.valor_cobrado
FROM cobranca c
LEFT JOIN execucao e
  ON e.atendimento_id = c.atendimento_id
 and e.procedimento_id = c.procedimento_id
WHERE e.atendimento_id IS NULL
ORDER BY c.id;
SELECT COUNT(*) AS linhas, SUM(c.valor_cobrado) AS total
FROM cobranca c
LEFT JOIN execucao e
  ON e.atendimento_id = c.atendimento_id
 and e.procedimento_id = c.procedimento_id
WHERE e.atendimento_id IS NULL;

Para conferir: 30 linhas, somando R$ 25.462,00 cobrados por serviços que não constam como realizados.

4

Juntando os três erros

WITH · UNION ALL · GROUP BY
Situação

Agora você tem três listas, cada uma com um lote. Para saber qual lote concentra mais erros, empilhe as três e conte por lote. Cada lista vira um bloco do WITH, e o UNION ALL empilha as linhas.

ComandoO que fazNo dia a dia
WITH a AS (…), b AS (…)vários blocos nomeados, separados por vírgula“acima, repetidas e fantasmas”
UNION ALLempilha resultados com as mesmas colunas“as três listas numa só”
GROUP BY loteuma linha por lote“erros de cada lote”
ORDER BY erros DESC + LIMITo campeão primeiro, só os principais“o lote que foge do padrão”
Ferramenta nova · WITH com vários blocos e UNION ALL

Dá para ter vários blocos num WITH, separados por vírgula. UNION ALL empilha resultados com as mesmas colunas, mantendo todas as linhas. Aqui cada bloco devolve só o lote.

Sua missão
  • Escreva um WITH com três blocos, acima, repetidas e fantasmas, cada um devolvendo o lote das linhas com aquele erro.
  • Empilhe os três e conte os erros por lote, do maior para o menor. Qual lote foge do padrão?
Dica

Cada bloco usa a consulta da etapa correspondente, selecionando só c.lote (ou lote). No fim: SELECT lote, COUNT(*) FROM (SELECT lote FROM acima UNION ALL SELECT lote FROM repetidas UNION ALL SELECT lote FROM fantasmas) t GROUP BY lote ORDER BY 2 DESC.

Ver solução
WITH acima AS (
  SELECT c.lote
  FROM cobranca c
  JOIN procedimento p ON p.id = c.procedimento_id
  WHERE c.valor_cobrado > p.valor_tabela * c.quantidade
),
repetidas AS (
  SELECT lote
  FROM cobranca
  WHERE id NOT IN (SELECT MIN(id) FROM cobranca
                   GROUP BY atendimento_id, procedimento_id)
),
fantasmas AS (
  SELECT c.lote
  FROM cobranca c
  LEFT JOIN execucao e
    ON e.atendimento_id = c.atendimento_id
   and e.procedimento_id = c.procedimento_id
  WHERE e.atendimento_id IS NULL
)
SELECT lote, COUNT(*) AS erros
FROM (SELECT lote FROM acima
      UNION ALL SELECT lote FROM repetidas
      UNION ALL SELECT lote FROM fantasmas) t
GROUP BY lote
ORDER BY erros DESC
LIMIT 5;

Para conferir: o lote L-0830-C tem 34 erros. O segundo colocado tem 4.

5

Quem assinou o lote?

JOIN · DISTINCT · fechar o caso
Situação

Com o lote em mãos, falta a papelada: quem assinou, e quanto dinheiro está em jogo. Esse lote concentra os três tipos de erro de uma só vez, o que é difícil de acontecer por descuido.

ComandoO que fazNo dia a dia
JOIN faturistatroca o número pelo nome“quem assinou o lote”
DISTINCTcada nome uma vez só“o mesmo faturista em várias linhas”
COUNT(*) e SUM(…)tamanho e valor do lote“100 linhas, R$ 88.045,91”
SELECT verificar_caso5('…')função do jogo que confere a resposta“perguntar ao sistema se acertei”
Sua missão
  • Mostre o nome do faturista responsável pelo lote encontrado.
  • Some o valor total cobrado nesse lote e o número de linhas.
  • Confira o código do lote com SELECT verificar_caso5('L-0000-X');.
Dica

JOIN faturista f ON f.id = c.faturista_id e WHERE c.lote = '…'. Use DISTINCT no nome, porque o faturista aparece em cada linha do lote.

Ver solução
SELECT DISTINCT f.nome
FROM cobranca c
JOIN faturista f ON f.id = c.faturista_id
WHERE c.lote = 'L-0830-C';
SELECT COUNT(*) AS linhas, SUM(valor_cobrado) AS total
FROM cobranca
WHERE lote = 'L-0830-C';

Para conferir: Bianca Furtado assinou o lote L-0830-C. O lote tem 100 linhas e R$ 88.045,91 cobrados. A resposta do caso é o código do lote.
