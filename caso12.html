Caso 12: o lote que sumiu

DESVIO

9 de outubro de 2026 · Farmácia Central

Na sexta-feira, 9 de outubro de 2026, a auditoria da farmácia fechou a conta do lote IGH-2609-114 de imunoglobulina humana 5 g, um medicamento caro: cada frasco custa R$ 2.380,00. Entraram 120 frascos em 8 de setembro. Somando o que os setores aplicaram nos pacientes com o que sobrou nos estoques, faltam 13 frascos. É quase R$ 31 mil.

O lote não ficou parado. Foi do Almoxarifado para a Farmácia Central, de lá para as farmácias satélites (da UTI e da Oncologia) e delas para os setores, sempre com uma guia de transferência. Uma guia pode virar várias: a satélite recebe 40 frascos e divide em quatro entregas. O caminho do lote é uma árvore, que vai se abrindo em galhos.

E tem um detalhe chato: o sistema antigo só anota o número do lote na primeira guia. As outras dizem apenas de qual guia_anterior vieram os frascos. Para seguir o lote é preciso andar de guia em guia, como quem puxa um fio. A resposta deste caso é o nome completo de quem fez os frascos sumirem.

A novidade deste caso é o WITH RECURSIVE: uma consulta que usa o próprio resultado para dar o próximo passo. É a ferramenta certa para árvores (uma guia que se divide em várias), caminhos (por onde o frasco passou), redes com ciclos (rotas que vão e voltam) e hierarquias (quem é chefe de quem). Ajuda ter feito o Caso 5, que usa WITH e UNION ALL. Travou? Abra a dica, depois a solução.

Atenção: nas datas deste caso

Aqui enviado_em, recebido_em e registrado_em são instantes com data e hora (timestamp), e chegou_em é uma data (date). Escreva entre aspas simples: ano-mês-dia, espaço, hora:minuto:segundo.

Puxando o fio: a primeira consulta recursiva

WITH RECURSIVE · âncora · UNION ALL · nível
Situação

A guia de entrada do lote IGH-2609-114 é fácil de achar: é a única com o lote preenchido. As guias que saíram dela têm guia_anterior igual ao id dela. As que saíram dessas apontam para elas, e assim por diante. O problema: você não sabe quantos andares essa árvore tem. Daria para fazer um JOIN para cada andar, mas quantos? Dois? Cinco? É aqui que entra a recursão.

ComandoO que fazNo dia a dia
WITH RECURSIVE nome AS (…)cria uma consulta que pode usar o próprio resultado“seguir a corrente de guias”
parte âncorao ponto de partida; roda uma vez só“a guia de entrada do lote”
UNION ALLjunta cada rodada nova ao que já foi achado“empilha as guias encontradas”
parte recursivaacha o próximo elo a partir do último achado“as guias que saíram destas”
nivel + 1conta em que andar da árvore a linha está“a quantas entregas da entrada”
Ferramenta nova · WITH RECURSIVE, em duas partes

Um WITH RECURSIVE tem sempre duas consultas grudadas por UNION ALL. A primeira é a âncora: o ponto de partida, que roda uma vez e não fala do próprio WITH. A segunda é a parte recursiva: ela faz JOIN com o próprio nome do WITH para achar o próximo passo. O banco roda em rodadas: a âncora dá as primeiras linhas; a parte recursiva olha só as linhas da rodada anterior e acha as seguintes; essas novas viram a base da próxima rodada. Quando uma rodada não acha nada, ele para e devolve tudo o que empilhou.

partena árvore do lote
âncoraSELECT … FROM lote_guia WHERE lote = 'IGH-2609-114': a guia de entrada, com 1 AS nivel
parte recursivaSELECT g.… , a.nivel + 1 FROM lote_guia g JOIN arvore a ON g.guia_anterior = a.id: as guias cuja guia anterior já está na árvore
paradaquando nenhuma guia aponta para as da última rodada, a árvore acabou
Veja as rodadas com um exemplo pequeno

Antes da árvore, um contador. A âncora começa em 1; a parte recursiva soma 1 ao número da rodada anterior; o WHERE n < 5 é a condição de parada. Sem ela, a conta nunca acabaria.

rodadade onde vemlinha nova
1âncora: SELECT 11
2recursiva: 1 + 1 (1 < 5, continua)2
3 e 4recursiva: 2 + 1, depois 3 + 13, 4
5recursiva: 4 + 15
6recursiva: 5 não é menor que 5, nada novopara
-- Um contador recursivo de 1 a 5 (não é missão, é para ver a recursão funcionando)
WITH RECURSIVE contagem AS (
  SELECT 1 AS n              -- âncora: o ponto de partida
  UNION ALL
  SELECT n + 1               -- parte recursiva: o próximo passo
  FROM contagem
  WHERE n < 5                -- condição de parada
)
SELECT n FROM contagem;
Por que UNION ALL, e não UNION?

UNION ALL empilha tudo, sem conferir repetição: é rápido e é o normal na recursão. UNION (sem ALL) jogaria fora linhas idênticas a cada rodada. Aqui cada guia tem um id diferente, então não há o que jogar fora: use UNION ALL. As colunas das duas partes precisam bater em número, ordem e tipo, como em qualquer UNION.

  • Numa linha só: quantas guias tem a árvore (guias) e quantos níveis ela tem (niveis).
Dica

A âncora é SELECT id, guia_anterior, origem, destino, 1 AS nivel FROM lote_guia WHERE lote = 'IGH-2609-114'. A parte recursiva pega as colunas de g (lote_guia g) e a.nivel + 1, com JOIN arvore a ON g.guia_anterior = a.id. Depois do WITH, um SELECT … FROM arvore comum. Na segunda missão, troque o SELECT final por COUNT(*) e MAX(nivel).

Ver solução

)
SELECT id, guia_anterior, origem, destino, nivel
FROM arvore
ORDER BY nivel, id;

No nível 2, três guias saem da Farmácia Central: uma para a SAT-UTI e duas para a SAT-ONC. No nível 3 estão as 10 entregas das satélites. O caminho de cada frasco e a conta de cada lote

caminho com || · levar a âncora até o fim · SUM sobre a árvore
Situação

O nivel diz em que andar a guia está, mas não por onde os frascos passaram. Dá para a recursão ir escrevendo o caminho, um lugar de cada vez. E tem outra pergunta: será que só este lote tem perda? Para comparar, é preciso montar a árvore de todos os lotes de uma vez e somar a diferença entre enviado e recebido em cada uma.

ComandoO que fazNo dia a dia
origem || ' → ' || destinogruda textos, formando o começo do caminho“ALM → FC”
a.caminho || ' → ' || g.destinoa cada rodada, acrescenta o novo destino“ALM → FC → SAT-UTI”
a.lote na parte recursivaleva um valor da âncora até as últimas guias“de que lote é esta guia?”
SUM(…) … GROUP BY depois do WITHsoma em cima da árvore pronta“perda total de cada lote”
Ferramenta nova · uma coluna que cresce a cada rodada

Na âncora, crie o começo do caminho: origem || ' → ' || destino AS caminho (o || gruda textos). Na parte recursiva, pegue o caminho que já veio da rodada anterior e acrescente o novo destino: a.caminho || ' → ' || g.destino. Cada guia sai com o seu caminho completo, desde a entrada. O mesmo truque serve para levar uma informação da âncora até o fim: só a guia de entrada tem o lote, mas se a parte recursiva repetir a.lote, todas as guias da árvore saem com o lote da sua entrada.

rodadaguiacaminho
âncoraALM → FCALM → FC
2FC → SAT-UTIALM → FC + → SAT-UTI
3SAT-UTI → UTI-AALM → FC → SAT-UTI + → UTI-A
Cuidado com o tipo

A coluna precisa ter o mesmo tipo nas duas partes. origem || ' → ' || destino já é texto, então tudo bem. Se a âncora começasse com um texto solto, como 'início' AS caminho, escreva 'início'::text para o banco não reclamar.

A recursão monta; o resto vem depois

Depois que o WITH RECURSIVE termina, o resultado é uma tabela como outra qualquer. Dá para filtrar, juntar com outras tabelas, agrupar e somar no SELECT final. Para começar de todos os lotes ao mesmo tempo, troque o filtro da âncora por WHERE guia_anterior IS NULL: são todas as guias de entrada.

Sua missão

  • Agora todos os lotes: comece por todas as guias de entrada, leve o lote até o fim da árvore e some qtd_enviada - qtd_recebida de todas as guias de cada lote. Mostre lote e perda, só os lotes com perda maior que zero, da maior para a menor.
Dica

Primeira: a âncora tem origem || ' → ' || destino AS caminho, e a parte recursiva tem a.caminho || ' → ' || g.destino. Segunda: âncora com lote e WHERE guia_anterior IS NULL; na parte recursiva, a.lote no lugar de g.lote. Fora do WITH: GROUP BY lote, HAVING SUM(qtd_enviada - qtd_recebida) > 0 e ORDER BY perda DESC.

Ver solução

  FROM lote_guia
  WHERE lote = 'IGH-2609-114'
  UNION ALL
  SELECT g.id, a.caminho || ' → ' || g.destino, g.qtd_enviada, g.qtd_recebida
  FROM lote_guia g
  JOIN arvore a ON g.guia_anterior = a.id
)
SELECT id, caminho, qtd_enviada, qtd_recebida
FROM arvore
ORDER BY caminho, id;
WITH RECURSIVE arvore AS (
  SELECT id, lote, qtd_enviada, qtd_recebida
  FROM lote_guia
  WHERE guia_anterior IS NULL
  UNION ALL
  SELECT g.id, a.lote, g.qtd_enviada, g.qtd_recebida
  FROM lote_guia g
  JOIN arvore a ON g.guia_anterior = a.id
)
SELECT lote, SUM(qtd_enviada - qtd_recebida) AS perda
FROM arvore
GROUP BY lote

ORDER BY perda DESC;

O lugar SAT-ONC aparece duas vezes, mas as guias são diferentes (uma ida e uma devolução), então a árvore não anda em círculo. Rotas que andam em círculo

ARRAY · = ANY · evitar ciclo · vários WITH
Situação

A farmácia tem um mapa das transferências autorizadas, a tabela lote_rota. Partindo do Almoxarifado e seguindo as rotas, dá para saber todos os lugares aonde um medicamento pode chegar de forma legítima. Se alguma guia do lote foi para um lugar fora desse mapa, achamos um furo. Só que as rotas, ao contrário das guias, formam círculos: FC → SAT-ONC é abastecimento e SAT-ONC → FC é devolução. Uma recursão ingênua ficaria indo e voltando para sempre.

ComandoO que fazNo dia a dia
ARRAY['ALM', destino]cria uma lista com os lugares já visitados“por onde já passei”
a.caminho || r.destinoacrescenta um lugar no fim da lista“mais um passo”
r.destino = ANY(a.caminho)verdadeiro se o lugar já está na lista“já passei aqui?”
WHERE NOT (…) na parte recursivanão volta a um lugar visitado“não andar em círculo”
WITH RECURSIVE a AS (…), b AS (…)vários WITH na mesma consulta“a árvore e o mapa juntos”
Ferramenta nova · lembrar por onde passou, para não andar em círculo

Na fase 1, a recursão parava sozinha: as guias acabam. Num mapa com ida e volta, ela não para. A solução é levar junto a lista de lugares já visitados, num ARRAY (uma coluna que guarda vários valores). A âncora começa a lista com ARRAY['ALM', destino]. A parte recursiva acrescenta o novo lugar com a.caminho || r.destino e, no WHERE, recusa voltar a um lugar que já está nela: NOT (r.destino = ANY(a.caminho)). O = ANY(lista) pergunta “esse valor é igual a algum da lista?”. Quando todos os próximos passos já foram visitados, a rodada não acha nada e a recursão para.

Veja o círculo acontecer (com freio de mão)

Esta consulta segue as rotas sem checar se já passou pelo lugar. Para ela não rodar para sempre, o WHERE v.nivel < 3 é um freio: para no terceiro passo. Repare nos caminhos que vão e voltam, como ALM → FC → ALM → FC. Nunca rode uma recursão num mapa com círculos sem uma condição de parada.

-- Sem checar lugar repetido: só não roda para sempre por causa do freio (nivel < 3)
WITH RECURSIVE volta AS (
  SELECT destino, 'ALM → ' || destino AS caminho, 1 AS nivel
  FROM lote_rota
  WHERE origem = 'ALM'
  UNION ALL
  SELECT r.destino, v.caminho || ' → ' || r.destino, v.nivel + 1
  FROM volta v
  JOIN lote_rota r ON r.origem = v.destino
  WHERE v.nivel < 3
)
SELECT caminho FROM volta WHERE nivel = 3 ORDER BY caminho;
Dois WITH na mesma consulta

Um WITH RECURSIVE pode ter vários blocos separados por vírgula, recursivos ou não: WITH RECURSIVE arvore AS (…), alcance AS (…) SELECT …. O RECURSIVE só aparece uma vez, logo depois do WITH, e vale para todos. No SELECT final você usa os dois, como se fossem tabelas.

Fora do WITH, GROUP BY destino com MIN(nivel). Segunda: junte a árvore da fase 1 e o alcance no mesmo WITH RECURSIVE, e filtre WHERE destino NOT IN (SELECT destino FROM alcance).

Ver solução

4

O elo quebrado

enviado × recebido · LEFT JOIN · SUM(…) FILTER
Situação

Voltando aos 3 frascos que a fase 2 achou: cada guia é um elo da corrente, com duas pontas. Quem mandou contou qtd_enviada; quem assinou o recebimento contou qtd_recebida. Se as contas não batem, o elo quebrou. Mas nem toda perda é sumiço: frasco quebra, e quando quebra, alguém assina um termo de baixa. Perda com termo é acidente registrado. Perda sem termo é o que interessa.

ComandoO que fazNo dia a dia
qtd_recebida < qtd_enviadacompara as duas pontas do mesmo elo“chegou menos do que saiu”
LEFT JOIN lote_baixatraz o termo de baixa, se existir“essa perda tem justificativa?”
JOIN com a árvoreusa o resultado da recursão como tabela“o nome de quem assinou”
SUM(x) FILTER (WHERE …)soma só as linhas que cumprem a condição“com termo e sem termo, numa linha”
Ferramenta nova · a árvore vira tabela para os JOINs de sempre

Até aqui a árvore só tinha colunas de lote_guia. Mas, depois que o WITH RECURSIVE termina, ela pode entrar em qualquer JOIN: com lote_funcionario para trocar o número de recebido_por pelo nome, e com lote_baixa para ver se existe um termo. Use LEFT JOIN no termo, porque a maioria das guias não tem nenhum, e você quer ver justamente as que ficaram sem. Para contar com e sem termo numa linha só, o FILTER que você viu com COUNT também funciona com SUM: SUM(x) FILTER (WHERE b.id IS NULL).

  • Numa linha só: quantos frascos se perderam com termo de baixa (com_baixa) e quantos sem (sem_baixa), nessa árvore.

Quem responde pelo trecho

hierarquia recursiva · descer e subir a chefia · tudo junto
Situação

Os problemas estão todos no mesmo trecho: guias que saíram da Farmácia Satélite da Oncologia. Quem responde por esse estoque é a equipe da satélite, e a equipe é uma hierarquia: a farmacêutica responsável, quem responde a ela, quem responde a essa pessoa… É outra árvore, agora de gente, guardada em chefe_id. A mesma recursão serve para descer (a equipe de alguém) e para subir (a cadeia de chefia de alguém).

ComandoO que fazNo dia a dia
ON f.chefe_id = e.iddesce: quem tem como chefe alguém que já está na lista“a equipe da farmacêutica”
ON f.id = c.chefe_idsobe: o chefe de quem já está na lista“a quem essa pessoa responde”

Ferramenta nova · a mesma recursão, para cima ou para baixo

Para descer: a âncora é o chefe, e a parte recursiva busca quem tem chefe_id igual a alguém já achado (JOIN equipe e ON f.chefe_id = e.id). Para subir: a âncora é a pessoa, e a parte recursiva busca o chefe de quem já foi achado (JOIN cadeia c ON f.id = c.chefe_id). A tabela é a mesma; só muda o lado do JOIN. Subindo, a recursão para sozinha em quem está no topo, porque o chefe_id nulo não liga com ninguém.

-- Exemplo: a cadeia de chefia de Nara Vilela, da UTI Pediátrica, subindo até o topo
WITH RECURSIVE cadeia AS (
  SELECT id, nome, cargo, chefe_id, 1 AS nivel
  FROM lote_funcionario
  WHERE nome = 'Nara Vilela'
  UNION ALL
  SELECT f.id, f.nome, f.cargo, f.chefe_id, c.nivel + 1
  FROM lote_funcionario f
  JOIN cadeia c ON f.id = c.chefe_id
)
SELECT nome, cargo, nivel FROM cadeia ORDER BY nivel;

Dica

Primeira: âncora SELECT id, nome, cargo, 1 AS nivel, nome AS cadeia FROM lote_funcionario WHERE id = (SELECT responsavel_id FROM lote_local WHERE codigo = 'SAT-ONC'); parte recursiva com JOIN equipe e ON f.chefe_id = e.id e e.cadeia || ' → ' || f.nome. Segunda: é o exemplo acima, com 'Hélio Loureiro'. Terceira: um WITH RECURSIVE com três blocos (arvore, alcance e equipe). No SELECT final, LEFT JOIN lote_baixa, a condição destino NOT IN (SELECT destino FROM alcance) OR (qtd_recebida < qtd_enviada AND b.id IS NULL), e enviado_por IN (SELECT id FROM equipe). Para os frascos, um CASE: se o destino está fora do mapa, conte qtd_enviada; se não, a diferença.

Ver solução
WITH RECURSIVE equipe AS (
  SELECT id, nome, cargo, 1 AS nivel, nome AS cadeia
  FROM lote_funcionario
  WHERE id = (SELECT responsavel_id FROM lote_local WHERE codigo = 'SAT-ONC')
  UNION ALL
  SELECT f.id, f.nome, f.cargo, e.nivel + 1, e.cadeia || ' → ' || f.nome
  FROM lote_funcionario f
  JOIN equipe e ON f.chefe_id = e.id
)
SELECT nome, cargo, nivel, cadeia
FROM equipe
ORDER BY nivel, nome;
WITH RECURSIVE cadeia AS (
  SELECT id, nome, cargo, chefe_id, 1 AS nivel
  FROM lote_funcionario
  WHERE nome = 'Hélio Loureiro'
  UNION ALL
  SELECT f.id, f.nome, f.cargo, f.chefe_id, c.nivel + 1
  FROM lote_funcionario f
  JOIN cadeia c ON f.id = c.chefe_id
)
SELECT nome, cargo, nivel
FROM cadeia
ORDER BY nivel;
WITH RECURSIVE arvore AS (
  SELECT id, destino, qtd_enviada, qtd_recebida, enviado_por
  FROM lote_guia
  WHERE lote = 'IGH-2609-114'
  UNION ALL
  SELECT g.id, g.destino, g.qtd_enviada, g.qtd_recebida, g.enviado_por
  FROM lote_guia g
  JOIN arvore a ON g.guia_anterior = a.id
),
alcance AS (
  SELECT destino, ARRAY['ALM', destino] AS caminho
  FROM lote_rota
  WHERE origem = 'ALM'
  UNION ALL
  SELECT r.destino, a.caminho || r.destino
  FROM alcance a
  JOIN lote_rota r ON r.origem = a.destino
  WHERE NOT (r.destino = ANY(a.caminho))
),
equipe AS (
  SELECT id
  FROM lote_funcionario
  WHERE id = (SELECT responsavel_id FROM lote_local WHERE codigo = 'SAT-ONC')
  UNION ALL
  SELECT f.id
  FROM lote_funcionario f
  JOIN equipe e ON f.chefe_id = e.id
)
SELECT f.nome,
       COUNT(*) AS guias,
       SUM(CASE WHEN a.destino NOT IN (SELECT destino FROM alcance) THEN a.qtd_enviada
                ELSE a.qtd_enviada - a.qtd_recebida END) AS frascos
FROM arvore a
JOIN lote_funcionario f ON f.id = a.enviado_por
LEFT JOIN lote_baixa b ON b.guia_id = a.id
WHERE (a.destino NOT IN (SELECT destino FROM alcance)
       OR (a.qtd_recebida < a.qtd_enviada AND b.id IS NULL))
  AND a.enviado_por IN (SELECT id FROM equipe)
GROUP BY f.nome;
