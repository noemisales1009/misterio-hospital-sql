1

Abrir a gaveta

SELECT · FROM · LIMIT · COUNT
Para que serve

Toda consulta começa assim: o que eu quero ver e de onde. É como pedir no arquivo: “me mostra a gaveta de relatórios”. Sem isso, você não enxerga nada do banco.

ComandoO que fazNo dia a dia
SELECTescolhe as colunas“quero ver nome e setor”
*todas as colunas“me mostra a ficha inteira”
FROMdiz qual tabela“da gaveta de relatórios”
LIMIT 10traz só as 10 primeiras“só as 10 de cima, por favor”

Rode estes exemplos
SELECT * FROM relatorio_ocorrencia LIMIT 10;
SELECT COUNT(*) FROM relatorio_ocorrencia;
SELECT data, tipo, setor FROM relatorio_ocorrencia LIMIT 5;
Sua missão

Descubra quantas pessoas existem na tabela pessoa.

Dica

Use o mesmo COUNT(*) do exemplo, só trocando o nome da tabela.

Ver solução
SELECT COUNT(*) FROM pessoa;

Deve dar 655. Viu? Ninguém consegue ler 655 fichas no olho. Por isso precisamos dos filtros da próxima fase.

2

O relatório perdido

WHERE · AND · OR
Para que serve

WHERE é o filtro. Igual ao filtro do Excel, ou quando você filtra na lista de leitos só os “ocupados” da UTI. AND junta condições: todas precisam ser verdade. OR aceita qualquer uma.

RegraExemplo
Texto vai entre aspas simplestipo = 'furto'
Número vai sem aspasdata = 20260310
Datas aqui são números AAAAMMDD10/03/2026 vira 20260310
Texto diferencia maiúscula, minúscula e acento'Furto' ≠ 'furto'
Exemplos
SELECT * FROM relatorio_ocorrencia
WHERE tipo = 'furto';
SELECT * FROM relatorio_ocorrencia
WHERE tipo = 'furto' AND setor = 'Farmácia';
Sua missão

Ache o relatório da ocorrência. Você lembra: foi uma sabotagem, em 10/03/2026, na Sala de Vacinas. Leia a descrição com atenção: ela fala de duas testemunhas.

Dica

Você precisa de três condições ligadas por AND: uma para data, uma para tipo e uma para setor. Se aparecerem vários resultados, falta alguma condição.

Ver solução
SELECT * FROM relatorio_ocorrencia
WHERE data = 20260310
  AND tipo = 'sabotagem'
  AND setor = 'Sala de Vacinas';

Anote as duas pistas: a primeira testemunha mora na última casa da Rua das Acácias; a segunda se chama Lorena e mora na Avenida dos Ipês.

3

Caçando as testemunhas

LIKE · % · ORDER BY · DESC
Para que serve

Às vezes você só sabe parte do nome. É como buscar um paciente no sistema digitando só “Lor”. O % é um curinga que significa “qualquer coisa aqui”. E o ORDER BY organiza a lista, igual ordenar uma coluna da planilha do maior pro menor.

EscrevendoEncontra
LIKE 'Ana%'começa com Ana: Ana Silva, Ana Lorena…
LIKE '%Silva'termina com Silva
LIKE '%Lor%'tem “Lor” em qualquer lugar
ORDER BY idadedo menor pro maior (crescente)
ORDER BY idade DESCdo maior pro menor (decrescente)

Com curinga, use LIKE no lugar de =. No Supabase (Postgres) existe também o ILIKE, que ignora maiúscula e minúscula.

Exemplos
SELECT * FROM pessoa
WHERE nome LIKE 'Ana%';
-- as 3 pessoas que moram nos maiores números da Rua do Sol
SELECT nome, numero_endereco FROM pessoa
WHERE rua_endereco = 'Rua do Sol'
ORDER BY numero_endereco DESC
LIMIT 3;
Sua missão

Encontre as duas testemunhas e anote o id de cada uma:

  • Testemunha 1: mora na última casa (maior número) da Rua das Acácias.
  • Testemunha 2: chama-se Lorena e mora na Avenida dos Ipês.
Dica

Testemunha 1: filtre pela rua, ordene numero_endereco com DESC e pegue só 1 com LIMIT 1.

Testemunha 2: use nome LIKE 'Lorena%' junto com a rua. Cuidado: existe mais de uma Lorena na cidade.

Ver solução
SELECT * FROM pessoa
WHERE rua_endereco = 'Rua das Acácias'
ORDER BY numero_endereco DESC
LIMIT 1;
SELECT * FROM pessoa
WHERE nome LIKE 'Lorena%'
  AND rua_endereco = 'Avenida dos Ipês';
4

Ouvindo as testemunhas

JOIN · ON · IN
Para que serve

Os depoimentos estão em outra tabela e só têm o pessoa_id, sem o nome. O JOIN cola duas tabelas lado a lado usando o número que elas têm em comum. É exatamente o que acontece quando você bipa a pulseira do paciente e o sistema puxa o prontuário dele.

flowchart LR
  A["pessoa
id = 10234
nome = Maria"] -- "pessoa.id = depoimento.pessoa_id" --> B["depoimento
pessoa_id = 10234
transcricao = ..."]
  B --> C["Resultado
Maria + o que ela disse"]
Exemplo
SELECT pessoa.nome, depoimento.transcricao
FROM pessoa
JOIN depoimento ON depoimento.pessoa_id = pessoa.id
LIMIT 5;

Lendo em voz alta: “pegue pessoa, junte com depoimento onde o pessoa_id do depoimento for igual ao id da pessoa”.

Para escrever menos, dá pra dar apelidos às tabelas: pessoa p e depoimento d. Para filtrar vários valores de uma vez, use IN (1, 2, 3).

SELECT p.nome, d.transcricao
FROM pessoa p
JOIN depoimento d ON d.pessoa_id = p.id
WHERE p.id IN (11111, 22222);  -- troque pelos ids das testemunhas
Sua missão

Leia os depoimentos das duas testemunhas. Marque com marca-texto mental cada pista: academia, número de sócio, plano, placa e a data em que a Lorena viu o suspeito.

Dica

Use o último exemplo trocando os números pelos ids que você achou na Fase 3. Se não anotou, dá pra filtrar pelo nome: WHERE p.nome IN ('Nome 1', 'Nome 2').

Ver solução
SELECT p.nome, d.transcricao
FROM pessoa p
JOIN depoimento d ON d.pessoa_id = p.id
WHERE (p.rua_endereco = 'Rua das Acácias' AND p.numero_endereco = (SELECT MAX(numero_endereco) FROM pessoa WHERE rua_endereco = 'Rua das Acácias'))
   OR (p.nome LIKE 'Lorena%' AND p.rua_endereco = 'Avenida dos Ipês');

Esse (SELECT MAX(...)) dentro de outra consulta se chama subconsulta. Você vai usar mais no bônus.

A pista da academia

JOIN + LIKE + vários filtros
Para que serve

Agora você junta tudo que aprendeu numa consulta só. É como montar um filtro no sistema do hospital: “pacientes da UTI e com prescrição de antibiótico e internados ontem”. Cada pista vira uma linha do WHERE.

As tabelas são academia_membro (os sócios) e academia_checkin (as entradas na catraca). Elas se ligam por academia_checkin.membro_id = academia_membro.id.

Sua missão

Liste os sócios que batem com as três pistas. Vão sobrar alguns suspeitos. Quantos?

Dica
SELECT m.id, m.nome, m.plano, c.data
FROM academia_membro m

6

Fechando o cerco

JOIN de 4 tabelas · verificar_solucao
Para que serve

Um JOIN pode ser encadeado, como vagões de trem. A placa está em habilitacao, que se liga a pessoa, que se liga a academia_membro, que se liga a academia_checkin. No mundo real é assim que um sistema hospitalar cruza paciente, leito, prescrição e farmácia.

flowchart LR
  C[academia_checkin] -- membro_id = id --> M[academia_membro]
  M -- pessoa_id = id --> P[pessoa]
  P -- habilitacao_id = id --> H[habilitacao]
Sua missão

Pegue a consulta da Fase 5 e acrescente mais dois JOINs para chegar na placa. Filtre a placa que contém H42W. Quando achar o nome, confirme no Supabase:

SELECT verificar_solucao('Nome Completo Aqui');
Dica

Acrescente embaixo dos outros JOINs:

JOIN pessoa p ON p.id = m.pessoa_id
JOIN habilitacao h ON h.id = p.habilitacao_id

E no WHERE: AND h.placa LIKE '%H42W%'. O % dos dois lados porque o H42W está “no meio” da placa.

Ver solução
SELECT p.nome, m.id, h.placa
FROM academia_checkin c
JOIN academia_membro m ON m.id = c.membro_id
JOIN pessoa p ON p.id = m.pessoa_id
JOIN habilitacao h ON h.id = p.habilitacao_id
WHERE m.id LIKE '48Z%'
  AND m.plano = 'ouro'
  AND c.data = 20260309
  AND h.placa LIKE '%H42W%';

Depois rode verificar_solucao com o nome que apareceu. E leia o depoimento dessa pessoa (Fase 4 de novo, com o id dela). Ela tem algo a contar.

Bônus: quem mandou?

BETWEEN · GROUP BY · HAVING · COUNT
Para que serve

GROUP BY junta linhas iguais num monte só, e COUNT conta quantas tem em cada monte. É o que você faria para saber “quantas notificações cada setor abriu no mês”. HAVING é o WHERE dos montes: filtra depois de contar. BETWEEN pega uma faixa, tipo “altura entre 165 e 170”.

Exemplo: quantas pessoas foram a cada evento
SELECT nome_evento, COUNT(*) AS presencas
FROM evento_checkin
GROUP BY nome_evento
ORDER BY presencas DESC;
Exemplo: quem foi a algum evento mais de 2 vezes
SELECT pessoa_id, COUNT(*) AS vezes
FROM evento_checkin
GROUP BY pessoa_id
HAVING COUNT(*) > 2;
Missão final

Use o depoimento do culpado para achar a pessoa que pagou pela sabotagem. Desafio extra do jogo original: tente resolver com no máximo 2 consultas.

Ver solução
SELECT p.nome, COUNT(*) AS vezes, r.renda_anual
FROM pessoa p
JOIN habilitacao h    ON h.id = p.habilitacao_id
JOIN evento_checkin e ON e.pessoa_id = p.id
JOIN renda r          ON r.cpf = p.cpf
WHERE h.genero = 'feminino'
  AND h.cor_cabelo = 'ruivo'
  AND h.altura_cm BETWEEN 165 AND 170
  AND h.marca_carro = 'Tesla'
  AND h.modelo_carro = 'Model S'
  AND e.nome_evento = 'Congresso de Gestão Hospitalar'
  AND e.data BETWEEN 20251201 AND 20251231
GROUP BY p.nome, r.renda_anual
HAVING COUNT(*) = 3;

Repare no JOIN renda ON r.cpf = p.cpf: aqui a ligação não é pelo id, é pelo CPF. Confirme com verificar_solucao.

Extra: seu caderno de detetive

CREATE TABLE · INSERT · UPDATE · DELETE
Para que serve

Até agora você só leu dados. Nesta fase você cria e guarda dados seus. É a parte que todo app usa: quando alguém abre uma notificação de evento adverso, o sistema faz um INSERT; quando o leito muda de status, faz um UPDATE. Pode fazer esta fase quando quiser, até no meio do jogo, para ir anotando as pistas.

ComandoO que fazNo hospital
CREATE TABLEcria uma tabela nova, vaziaimprimir um formulário em branco
INSERTcoloca uma linha novapreencher uma ficha nova
UPDATEmuda uma linha que já existecorrigir a ficha
DELETEapaga linhasrasgar uma ficha errada
Passo 1 · Criar a tabela

Cada coluna tem um nome e um tipo, que diz que tipo de informação cabe ali. É como um formulário que só aceita número no campo “leito”.

TipoGuardaExemplo
bigint … IDENTITYnúmero que o banco gera sozinho: 1, 2, 3…número da ficha
integernúmero inteirofase 3
texttexto de qualquer tamanho“placa tem H42W”
booleanverdadeiro ou falsopista confirmada?
timestamptzdata e horaquando anotei
CREATE TABLE caderno (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  fase        integer,
  pista       text NOT NULL,
  suspeito    text,
  confirmada  boolean DEFAULT false,
  criado_em   timestamptz DEFAULT now()
);
  • PRIMARY KEY: o número único de cada anotação.
  • NOT NULL: a pista é obrigatória, não dá para salvar em branco.
  • DEFAULT: valor automático quando você não preenche. A data e hora entram sozinhas com now().

Depois de rodar, abra o Table Editor: a tabela caderno aparece lá, vazia.

Passo 2 · Anotar pistas com INSERT
INSERT INTO caderno (fase, pista)
VALUES (2, 'Sabotagem na Sala de Vacinas em 10/03/2026');

Repare: você não preenche id, confirmada nem criado_em. O banco faz isso. Dá para anotar várias de uma vez, separando por vírgula:

INSERT INTO caderno (fase, pista, suspeito) VALUES
  (3, 'Testemunha 1 mora na última casa da Rua das Acácias', NULL),
  (5, 'Sócio 48Z, plano ouro, treinou em 09/03', 'Jeremias Paiva');
SELECT * FROM caderno ORDER BY id;
Passo 3 · Corrigir com UPDATE

UPDATE sempre vem com WHERE. Sem ele, o banco muda todas as linhas. É como corrigir uma prescrição: você precisa dizer qual paciente.

UPDATE caderno
SET confirmada = true
WHERE id = 1;
Passo 4 · Apagar com DELETE

Mesma regra: sempre com WHERE. Um DELETE FROM caderno; sozinho apaga o caderno inteiro e não tem desfazer.

DELETE FROM caderno
WHERE suspeito = 'Jeremias Paiva';
Passo 5 · Truque de mestre: salvar o resultado de uma busca

Dá para juntar INSERT com SELECT. O banco busca e já anota no caderno, sem você copiar nada à mão. É assim que automações (como no n8n) gravam relatórios.

INSERT INTO caderno (fase, pista, suspeito)
SELECT 4, d.transcricao, p.nome
FROM pessoa p
JOIN depoimento d ON d.pessoa_id = p.id
WHERE p.nome LIKE 'Lorena%'
  AND p.rua_endereco = 'Avenida dos Ipês';
Sua missão
  • Crie a tabela caderno.
  • Anote pelo menos uma pista de cada fase que você já fez.
  • Marque como confirmada = true as pistas que você já conferiu.
  • Apague uma pista que se mostrou falsa.
  • Desafio: use INSERT … SELECT para salvar o depoimento da testemunha 1.
Dica para o desafio

Copie o exemplo do passo 5 e troque o WHERE pelo filtro da testemunha 1: a última casa da Rua das Acácias (lembra da subconsulta com MAX na Fase 4?).

Ver solução do desafio
INSERT INTO caderno (fase, pista, suspeito)
SELECT 4, d.transcricao, p.nome
FROM pessoa p
JOIN depoimento d ON d.pessoa_id = p.id
WHERE p.rua_endereco = 'Rua das Acácias'
  AND p.numero_endereco = (SELECT MAX(numero_endereco)
                           FROM pessoa
                           WHERE rua_endereco = 'Rua das Acácias');
Bom saber

Se você rodar o banco do jogo de novo para recomeçar, seu caderno não é apagado: o script só recria as tabelas do mistério. Para apagar o caderno de propósito: DROP TABLE caderno;

A

Contando e somando

DISTINCT · MIN · MAX · AVG · SUM · ROUND
Para que serve

Até aqui você listou linhas. Agora você vai resumir: quantos tipos existem, qual o maior valor, qual a média. É o que você faz numa planilha com a linha de totais no rodapé. DISTINCT tira os repetidos, e MIN, MAX, AVG e SUM calculam sobre a coluna inteira.

EscrevendoSignifica
DISTINCT tipocada tipo aparece uma vez só
COUNT(DISTINCT setor)quantos setores diferentes existem
MIN(x) / MAX(x)o menor e o maior valor
AVG(x)a média
SUM(x)a soma
ROUND(x, 1)arredonda para 1 casa decimal
Exemplos
-- cada tipo de ocorrência, sem repetir
SELECT DISTINCT tipo
FROM relatorio_ocorrencia
ORDER BY tipo;
-- a pessoa mais baixa e a mais alta
SELECT MIN(altura_cm), MAX(altura_cm)
FROM habilitacao;
Sua missão
  • Quantos setores diferentes aparecem nos relatórios de ocorrência?
  • Qual a menor e a maior renda anual da cidade?
  • Qual a renda média anual, arredondada sem casas decimais?
Dica

Para o item 1, junte COUNT com DISTINCT dentro do parêntese. Para o item 3, coloque o AVG dentro do ROUND.

Ver solução
SELECT COUNT(DISTINCT setor) FROM relatorio_ocorrencia;
SELECT MIN(renda_anual), MAX(renda_anual) FROM renda;
SELECT ROUND(AVG(renda_anual)) FROM renda;

Para conferir: 11 setores; renda de 18317 a 980000; média de 134334.

B

Consulta dentro de consulta

SUBCONSULTA · IN · = (SELECT …)
Para que serve

Às vezes a resposta de uma pergunta depende da resposta de outra. “Quem ganha acima da média?” primeiro pede a média, depois compara. Em SQL você escreve a primeira pergunta entre parênteses, dentro da segunda. É como abrir um prontuário para achar o número do leito e usar esse número para abrir outro.

EscrevendoSignifica
WHERE x > (SELECT AVG(x) …)compara com um valor calculado na hora
WHERE x = (SELECT MAX(x) …)pega quem tem o maior valor
WHERE id IN (SELECT …)o id está na lista que a subconsulta devolve
Exemplos
-- quem foi ao Congresso de Gestão Hospitalar (sem JOIN)
SELECT nome FROM pessoa
WHERE id IN (
  SELECT pessoa_id FROM evento_checkin
  WHERE nome_evento = 'Congresso de Gestão Hospitalar'
)
LIMIT 5;
-- renda acima da média
SELECT COUNT(*) FROM renda
WHERE renda_anual > (SELECT AVG(renda_anual) FROM renda);
Sua missão
  • Quantas pessoas ganham acima da média de renda?
  • Qual o nome da pessoa de maior renda anual?
  • Quantas pessoas que têm um carro da marca Tesla foram ao evento Show no Parque? Resolva só com IN e subconsultas.
Dica

Item 2: a subconsulta (SELECT MAX(renda_anual) FROM renda) devolve o valor. Use-o no WHERE de uma consulta que liga pessoa e renda pelo CPF. Item 3: use dois IN ligados por AND, um para a habilitação e outro para o evento.

Ver solução
SELECT COUNT(*) FROM renda
WHERE renda_anual > (SELECT AVG(renda_anual) FROM renda);
SELECT p.nome, r.renda_anual
FROM pessoa p
JOIN renda r ON r.cpf = p.cpf
WHERE r.renda_anual = (SELECT MAX(renda_anual) FROM renda);
SELECT COUNT(*) FROM pessoa
WHERE habilitacao_id IN (SELECT id FROM habilitacao WHERE marca_carro = 'Tesla')
  AND id IN (SELECT pessoa_id FROM evento_checkin WHERE nome_evento = 'Show no Parque');

Para conferir: 328 pessoas; Vitória Albuquerque; 11 pessoas.

C

Classificando com CASE

CASE · WHEN · THEN · ELSE · END
Para que serve

CASE é o “se isso, então aquilo” do SQL. Serve para criar uma coluna nova com uma etiqueta, como a classificação de risco do paciente: verde, amarelo ou vermelho, conforme os sinais. Depois você pode contar quantos caem em cada etiqueta com GROUP BY.

EscrevendoSignifica
WHEN condição THEN valorse a condição for verdadeira, usa este valor
ELSE valorse nenhuma condição bater, usa este
ENDfecha o CASE
AS nomedá nome à coluna criada
Exemplos
-- etiqueta nova para cada sócio
SELECT nome, plano,
  CASE WHEN plano = 'ouro' THEN 'VIP' ELSE 'comum' END AS categoria
FROM academia_membro
LIMIT 5;
-- contando por etiqueta
SELECT
  CASE WHEN altura_cm < 170 THEN 'mais baixa' ELSE 'mais alta' END AS grupo,
  COUNT(*) AS total
FROM habilitacao
GROUP BY grupo;
Sua missão
  • Separe a renda em três faixas: baixa (menos de 50000), média (de 50000 até 199999) e alta (200000 ou mais). Conte quantas pessoas há em cada faixa.
  • Classifique as ocorrências em grave (sabotagem, invasão, furto, fraude) e leve (as demais). Conte quantas há de cada.
Dica

Use CASE no SELECT, dê um nome com AS e repita esse nome no GROUP BY. As condições são testadas de cima para baixo, então coloque a menor faixa primeiro. No item 2, tipo IN ('sabotagem', …) resolve a condição.

Ver solução
SELECT
  CASE WHEN renda_anual < 50000  THEN 'baixa'
       WHEN renda_anual < 200000 THEN 'média'
       ELSE 'alta' END AS faixa,
  COUNT(*) AS total
FROM renda
GROUP BY faixa
ORDER BY total DESC;
SELECT
  CASE WHEN tipo IN ('sabotagem', 'invasão', 'furto', 'fraude') THEN 'grave'
       ELSE 'leve' END AS gravidade,
  COUNT(*) AS total
FROM relatorio_ocorrencia
GROUP BY gravidade
ORDER BY total DESC;

Para conferir: média 445, alta 128, baixa 82; grave 536 e leve 369.

D

Quem ficou de fora

LEFT JOIN · IS NULL
Para que serve

O JOIN que você já conhece só mostra quem tem par nas duas tabelas. Mas a pergunta, às vezes, é a contrária: quem não tem. Quais pacientes não têm retorno marcado? Quais sócios nunca foram? O LEFT JOIN mantém todo mundo da tabela da esquerda. Quem não achou par fica com NULL, e é só filtrar por IS NULL.

EscrevendoSignifica
JOINsó quem tem par nas duas tabelas
LEFT JOINtodos da esquerda, com ou sem par
IS NULLo valor está vazio (sem par)
IS NOT NULLo valor existe
Exemplos
-- todos os sócios, com ou sem entrada na academia
SELECT m.nome, c.data
FROM academia_membro m
LEFT JOIN academia_checkin c ON c.membro_id = m.id
LIMIT 5;
-- só quem nunca entrou
SELECT m.nome
FROM academia_membro m
LEFT JOIN academia_checkin c ON c.membro_id = m.id
WHERE c.membro_id IS NULL
LIMIT 5;
Sua missão
  • Quantos sócios da academia nunca entraram (não têm nenhum check-in)?
  • Desses, quantos há em cada plano?
  • Liste o nome dos sócios do plano ouro que nunca entraram, em ordem alfabética.
Dica

Parta de academia_membro (a esquerda) e faça LEFT JOIN com academia_checkin. Quem nunca entrou fica com c.membro_id IS NULL. Conte com COUNT(*) e, no item 2, agrupe por m.plano.

Ver solução
SELECT COUNT(*)
FROM academia_membro m
LEFT JOIN academia_checkin c ON c.membro_id = m.id
WHERE c.membro_id IS NULL;
SELECT m.plano, COUNT(*) AS total
FROM academia_membro m
LEFT JOIN academia_checkin c ON c.membro_id = m.id
WHERE c.membro_id IS NULL
GROUP BY m.plano
ORDER BY m.plano;
SELECT m.nome
FROM academia_membro m
LEFT JOIN academia_checkin c ON c.membro_id = m.id
WHERE c.membro_id IS NULL
  AND m.plano = 'ouro'
ORDER BY m.nome;

Para conferir: 28 sócios; bronze 8, ouro 11, prata 9; a lista do ouro tem 11 nomes.
